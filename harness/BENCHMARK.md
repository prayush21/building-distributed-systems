## Reading these numbers

- **Reduction vs FIFO** is `(FIFO_mr - policy_mr) / FIFO_mr`. Positive is
  better. FIFO's own row is 0 by construction.
- **Gap closed vs OPT** is `(LRU_mr - policy_mr) / (LRU_mr - OPT_mr)`. LRU
  is 0 and Belady is 100% by construction. Negative means worse than LRU.
- **Above 100% is possible and is not a bug.** Belady is provably optimal
  only when every object is the same size; with variable sizes, optimal
  offline caching is NP-hard and the Belady baseline is a strong upper
  bound rather than a true ceiling. Under `--ignore-obj-size` it is a true
  ceiling and values should not exceed 100%.
- **`—`** means undefined, not zero: either the run failed, or the
  denominator was too small to divide by. Gap closed is withheld when the
  LRU-to-OPT gap is under 1e-06, where the ratio would be noise.
- **ns/op** is measured over the in-memory replay loop, so it reflects the
  policy rather than trace parsing. It is still a wall-clock measurement
  on a shared machine and should be read as a rough cost, not a benchmark.
